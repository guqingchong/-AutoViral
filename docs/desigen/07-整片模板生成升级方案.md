## 一、问题 1：整片模板生成效果达不到 web 渲染效果

### 根源诊断：三条渲染栈的能力天花板不同

| 生成路线 | 渲染栈 | 表达力天花板 | 现状 |
|---|---|---|---|
| AI 生成模板（kind=video） | JSON VideoLayer → FFmpeg drawbox/drawtext | 最低：无渐变叠加、无辉光、无毛玻璃、动效只有 fadein/slidein | 有质检+评分门禁，但"不丑"≠"好看" |
| 代码整片模板（kind=code） | Revideo 2D Canvas | 中：有 spring/shadowBlur/圆角，但 API 表达力远不如 CSS | 有 fidelity 视觉校验，但校验只能保证"还原设计稿"，设计稿能被 Revideo 表达的部分本身就受限 |
| **web 支路（templates-web）** | **完整 CSS（color-mix/backdrop-filter/渐变/盒阴影）+ WAAPI** | **最高** | 昨天 20 款镜头模板已验证 |

关键结论：**fidelity 校验解决的是"渲染结果 ≠ 设计稿"，而用户感知的效果差距是"Revideo 能表达的 < web 能表达的"**——即使 100% 还原，Revideo 产物的材质感（辉光层次、毛玻璃、渐变网格、字距排版）仍逊于 CSS。这不是 prompt 问题，是渲染栈问题。

### 方案：整片模板开放 web 出口（与镜头模板同一渲染栈）

基建已在（2026-09-02 镜头模板生成渠道复用同一套）：

1. **生成端**：设计稿向导加「渲染支路」选择——Revideo TSX / Web HTML。Web 出口复用 `scene-template-generator.ts` 的契约（自包含 HTML/WAAPI/`__seek`/主题令牌），差别只在：
   - 参数契约用整片契约（title/kicker/subtitleCn/subtitleEn/videoSrc/videoRatio/duration，对齐 keynote-leather）
   - 时长跟随数字人源片（≤600s），字幕带避让规则相同
2. **存储**：`kind=code` 模板 `layers[0]` 增加 `customHtml` 字段（与现有 `customCode` TSX 并列），入库/编辑/再加工/fidelity 校验全复用。
3. **渲染端**：`startRender` 的 kind=code 分支判 `layers[0].customHtml` → 走 `renderCodeScene({customHtml})`（web-worker），否则走原 Revideo 路径。改动点约 30 行。
4. **演进策略**：新生成一律默认 web 出口；Revideo 出口保留兼容存量模板；keynote-leather 择机重写为 web 版（此前 Revideo 独占的唯一理由就是数字人源片中转，web-worker 同样可以 stage）。

**风险**：数字人视频窗口在 web 支路需 `<video src>` + staged 中转（现仅 keynote/custom 形态做了中转，customHtml 需补上 `videoSrc` staging——把 `stageDigitalHumanAsset` 的适用条件从 `(isKeynote || isCustom)` 扩到 `isCustomHtml` 即可，约 5 行）。

## 二、问题 2：分页模板（封面/正文/结尾）不会做、不会描述

### 现状诊断

- **图文模板早已是双页**（cover + contentPage 两个 LayoutSpec），但视频/代码模板没有分页概念：
  - JSON 时间线模板：单一时间线，`start` 聚类隐式成幕（`detectScenes` 只服务克隆模板的故事板），**生成 prompt 从未要求多幕结构**，所以 AI 生成的都是"一屏到底"；
  - 代码整片模板（含设计稿向导）：DesignBrief 模型是**单页**的（palette/layout/elements/motion 各一份），用户想说"封面要冲击、正文要克制、结尾要 CTA"没有字段可填。
- 用户侧痛点本质：**不是不会写自然语言，而是产品没有"页"这个概念的输入位**。

### 方案：DesignBrief 分页化 + 引导式分页描述

1. **模型扩展**（向后兼容）：
   ```ts
   interface DesignBrief {
     // ...现有字段作为"全局风格基调"保留
     pages?: Array<{
       role: "cover" | "content" | "ending";   // 封面/正文/结尾
       goal: string;                            // 本页目标(用户填:如"3秒抓住眼球")
       layout: Array<{region; content; position}>;  // 覆盖全局 layout
       motionOverride?: string;                 // 本页动效特例
       elementsExtra?: string[];                // 本页装饰增量(仍走白名单)
     }>;
   }
   ```
   无 pages 的 brief 视为单页（现状），渲染端零影响。
2. **UI：brief 卡片加分页标签页**（封面/正文/结尾三个 tab），每页一组引导式填空：
   - 本页目标（下拉常用项 + 自由输入：「3 秒抓眼球」/「承载核心论证」/「引导关注评论」）
   - 主视觉（下拉：大标题/数字人窗口/数据卡/金句/CTA 按钮）
   - 动效基调（下拉：冲击入场/平稳呼吸/强调收束）
   - 每页附「这样说更有效」示例 chips，点击即填入——解决"不知道怎么说"
3. **生成端**：
   - web 出口：单 HTML 内多屏（cover/content/ending 三个 scene 段，按 `__PARAMS__.duration` 比例分配时间轴，屏间切换用统一转场动效）——单文件契约不变，渲染端零改动；
   - Revideo 出口：单场景内分段生成器（同理）；
   - JSON 时间线路线：生成 prompt 增加三幕硬性结构（每幕一块全屏底版 shape 保证 `detectScenes` 聚类正确，封面幕 1.5-2.5s、结尾幕 2-3s），分幕灯箱已能逐幕预览。
4. **预览**：分幕灯箱（frameUrls）对多页模板天然适配——poster 端点按幕抽帧即可逐页查看。

### 用户速查表（落地后写进 UI 占位提示）

| 页 | 说什么 | 示例 |
|---|---|---|
| 封面 | 目标 + 主视觉 + 第一冲击力 | 「封面：深蓝底，大标题居中弹入，顶部小英文 kicker，2 秒内落定」 |
| 正文 | 信息密度 + 阅读秩序 | 「正文：标题居左上，主视觉区留 60% 给素材窗口，字幕区沉稳不抢戏」 |
| 结尾 | 收束动作 + 引导 | 「结尾：金句放大居中，底部一行关注引导，整体放慢收束」 |
