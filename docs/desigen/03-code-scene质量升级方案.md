# code-scene 程序化动画质量升级方案

> 2026-08-18，回应用户反馈：程序性讲解动画太粗糙、只有 3 种样式。

## 一、现状诊断

### 为什么只有 3 种样式

code-scene（Revideo 代码渲染素材层）8-14 上线时是 MVP：`flow-steps`（流程步骤）、`logic-chain`（逻辑链）、`structure-growth`（结构生长）三个手写模板，每个仅 60-80 行。虽然架构上支持 `customScene`（agent 自由编写 Revideo 场景代码），但实战中 agent 极少使用——无设计系统约束的自由生成质量不可控，且评审会打回。

### 为什么"粗糙"（技术归因）

对照标杆（回形针/柴知道级 motion graphics），差距在三层：

| 层 | 标杆做法 | 现状 |
|---|---|---|
| 动效语言 | 弹簧物理（spring）、错峰入场（stagger）、遮罩揭示（mask reveal）、数字滚动（count-up）、镜头推拉 | 仅淡入+滑入+脉冲三种线性补间 |
| 信息设计 | 图层叙事（背景网格/装饰线/来源标注）、字重三级以上、版式网格系统 | 单层卡片平铺，两级字号，无网格 |
| 品牌一致性 | 固定色板+组件库+转场语言 | 4 套色板但无组件库，模板间无共享转场 |

Revideo 引擎本身能力不是瓶颈（代码驱动，理论上什么都能画），瓶颈在模板数量与精细度。

## 二、升级方案（分两步）

### 第一步：模板库扩充 + 动效升级包（1-2 天）

**新增 7 个场景模板**（覆盖知识类视频主流视觉叙事模式）：

1. `big-number` 大数字冲击——关键数据全屏滚动计数+单位弹跳（经济数据类必备）
2. `compare-split` 对比对照——左右分屏双栏，逐项 PK 高亮（政策前后/方案对比）
3. `timeline` 时间轴——横向/纵向时间线推进，节点逐个激活（政策沿革）
4. `pyramid` 金字塔层级——自下而上堆叠构建（体系结构/层级关系）
5. `quote-card` 金句卡——大字逐词显现+来源标注（已有简易版，升级为排版精良版）
6. `checklist` 清单打勾——逐项打勾+划除动画（要点总结/避坑清单）
7. `map-points` 地图点位——区域地图+点位脉冲（地域分布类，用简化中国地图轮廓）

**动效升级包**（`src/motion.ts` 共享库）：
- spring 弹簧缓动替代线性 cubic
- stagger 错峰入场工具函数
- mask reveal 遮罩揭示
- count-up 数字滚动
- 背景网格/装饰线/角标组件（`src/components.ts` 共享版式件）
- 统一转场：场景间 wipe/fade 标准时长

### 第二步：custom scene 质量闭环（0.5-1 天）

让 agent 的 customScene 从"一次性裸写"变成"带护栏的迭代"：
- systemPrompt 注入设计系统约束（色板/字号层级/安全区/禁则）
- 渲染后自动走 vision 评审（已有基建），评审意见回喂 agent 改稿，最多 2 轮
- 优质 custom scene 沉淀回模板库（人工确认后入库）

## 三、验收标准

- 同一脚本分别用 5 个以上不同模板出片，视觉差异明显
- 评审"美学质量"维度从当前 8 分档提升到稳定 9 分
- 与标杆账号同主题片做盲测对比，"粗糙感"主观评价消除
