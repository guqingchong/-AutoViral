# Autoviral 全局体检报告(2026-08-24)

> 审查范围:部署就绪性 / 代码架构缺陷 / 功能完整性(三路并行审查 + 人工抽查核实)
> 结论:**当前状态 = 开发机源码模式可用,安装包在别的电脑上 100% 无法工作。不能封装发版。**

---

## 一、阻断部署(P0,不修则不能装机)

### A. Electron 打包后服务进程起不来(三层叠加,任一层致命)
1. `electron/main.cjs:9` spawn `dist/server/index.js`,但 `src/server/index.ts:102` 的 `startServer()` 只导出不自启,唯一调用方是 `src/cli.ts:115`。应 spawn `dist/index.js start --foreground`。
2. `electron-builder.yml` 未配 `asar: false`,产物是 `resources/app.asar` 而 `main.cjs:8` 找 `resources/app/` → existsSync 失败直接 quit。且 Node 子进程读不了 asar 内文件(前端静态目录、python 脚本都在包内路径)。
3. 无随包 Node 运行时(`bin/node.exe` 不存在,fallback 到 Electron 本体但没设 `ELECTRON_RUN_AS_NODE=1`);`better-sqlite3` 原生模块 ABI 也不匹配。

### B. bundled FFmpeg 三重路径错配
- 下载脚本产出 `bin/ffmpeg/bin/ffmpeg.exe`,代码找 `bin/ffmpeg/ffmpeg.exe`;
- extraResources 位置与 `AUTOVIRAL_APP_ROOT` 查找路径不一致;
- 最致命:`src/video/ffmpeg.ts:10-21` `getFFmpegPath()` 不读任何环境变量,只找 PATH → 新机器(无 ffmpeg)视频合成/探测/门禁全挂。

### C. packages/code-scene 不随包 → 代码渲染模板全挂
- `files` 不含 `packages/**`;postinstall.ts 是死代码(package.json:28 的 postinstall 只 echo);
- worker.mjs spawn "node" 假设目标机有系统 Node;Edge 路径只有两个 Windows 硬编码候选。

### D. Playwright 浏览器二进制不随包 → 登录/发布/截图全挂
- 所有 chromium.launch 未指定 channel/executablePath,浏览器在构建机 `%LOCALAPPDATA%\ms-playwright`,目标机首次调用即失败。

### E. 硬编码开发者机器绝对路径
- `src/ws-bridge.ts:359`、`skills/content-assembly/SKILL.md:17` 写死 `C\:/Users/顾庆冲/.autoviral/fonts` —— 换任何机器都不存在,且与"禁止系统字体"指令矛盾,agent 必卡死。

### F. 中文字体不会出现在新机器
- 渲染字体源 `~/.autoviral/fonts` 无任何代码填充;仓库 `fonts/` 只剩 Black 字重;`files` 不含 `fonts/**` → 字体回退 + agent 被指示"回退必须停下修正"= 死循环风险。

### G. HeyGem/H3 隧道默认值指向开发者私有 AutoDL 实例
- `src/config.ts:52-75` 硬编码私有实例地址且透出到设置 API;用户开启即连开发者实例(配合 ssh-key-service 自动传公钥,更糟)。

## 二、高危安全(P1,装机后=局域网裸奔)

1. **HTTP API 无鉴权 + 绑定 0.0.0.0**(`src/server/index.ts:207-236`)— 局域网任何人可操作全部功能。
2. **GET /api/config 明文回吐全部密钥**(api.ts:307-336,仅 llm 段脱敏)。
3. **平台 cookie 三处明文落库**(account-credentials/platform-credentials/accounts 表;credential-crypto 的 dev fallback key 硬编码)。
4. **路径穿越(读)**:`/api/works/:id/assets/..%2F..%2F` 可读磁盘任意文件(work-store.ts:434 + api.ts:743)。
5. **路径穿越(写)**:资产上传 subdir/文件名未 sanitize → 任意文件写(api.ts:858-861)。
6. **WebSocket 无鉴权**(`/ws/browser/:workId`,ws-bridge.ts:142-152)— 可接管 agent 会话,等于远程指挥 LLM 执行工具。
7. **/api/admin/backup 任意路径写 + restore zip-slip**(api.ts:5158、backup.ts:128-131)。
8. (中危)SSRF:stock-assets /download、template-clone、/api/llm/ping 接受任意 URL 服务端 fetch。

## 四、中低危与技术债(P3)

- 稳定性:unhandledRejection 只写日志;数字人轮询超时不落库(与文件内其他分支策略不一致);watchdog 不覆盖 reviewing 卡死;reconcile 60s 周期无重入保护;updateWork 多表写非事务(三套状态机不同步的根因,靠 reconcile 事后补救)。
- 部署体验:端口 3271 写死在 agent 提示词(9 处)+ Electron WEB_URL;无首启向导;DB 无定时备份/损坏自恢复;engines 声明 node>=18 失真(better-sqlite3 v12 需 20+);便携版数据目录随启动方式分裂;趋势调研依赖系统 Python 但文档未提;CLI dashboard 用 macOS open 命令。
- 测试盲区:71 个服务中 21 个无专属单测(reconcile/quality-gate/quota-guard/login-health/scheduler/publish-driver/素材渲染全链等)。
- 垃圾入库:git 跟踪了 undefined/autoviral.db、_server4.log、codex-review-*.log。
- 8-21 终审 deferred minors 12 项(画像目录哨兵不统一、预检未知态误述、串行验证等)。

## 五、修复路线图建议

**P0 部署阻断(约 3-5 天)**
1. Electron 入口改 spawn `dist/index.js start --foreground` + `ELECTRON_RUN_AS_NODE` 或随包 node.exe;asar 关闭或资源外置;
2. getFFmpegPath 读 FFMPEG_PATH + bundled 路径;统一 bin/ffmpeg 布局;
3. packages/code-scene(含 node_modules 裁剪)随包;worker Edge 候选扩充 + 系统 Chrome/Edge channel 回退;
4. Playwright 改 `channel: "msedge"`(Windows 自带 Edge,免分发浏览器)或安装器首启下载;
5. 清除全部硬编码绝对路径(字体路径改读 dataDir);fonts 随包并首启铺到 dataDir/fonts;
6. 隧道默认值清空改必填;
7. 增加打包后冒烟测试(CI 在干净 VM 跑一次启动+渲染+发布预检)。

**P1 安全(约 2-3 天)**
1. 绑定 127.0.0.1(桌面应用默认)+ 可选 token 鉴权;
2. /api/config 全量脱敏;cookie 统一走 credential-crypto,删 dev fallback;
3. 路径穿越两处 sanitize(workId/filename/subdir 白名单校验);
4. WS 鉴权;admin/backup 路径限制在 dataDir;
5. SSRF 三处加 URL 白名单/私网段拦截。

**P2 功能(按业务优先级)**
1. 视频号数据回收 adapter;
2. Settings 蝉镜/百炼死 UI 删除;
3. publish 接入 pipeline 步骤 + 产出物硬性存在性校验;
4. 图文模板预览图;
5. 首启环境体检向导(LLM key/ffmpeg/python/yt-dlp/Edge 一键检测)。

**P3 技术债**:updateWork 事务化、轮询失败落库策略统一、reconcile 重入保护、测试补盲、仓库垃圾清理、deferred minors 12 项。
