## 一、病根 10:隐性流程未固化,Agent 每轮重新发明轮子(Process Amnesia)

流水线跑了几十轮,但"每一步用什么工具、素材从哪搜、失败换什么"的经验
**从未沉淀为确定性子流程**。每个作品、每个回合,agent 都在开放式目标描述下
重新探索一遍。这不是模型笨,是系统把本该代码/prompt 固化的知识外包给了 LLM 的临场发挥。

### 量化证据(单作品 w_20260826_1652_224)

| 指标 | 数值 | 出处 |
|---|---|---|
| LLM 调用总数 | 634 次 | llm_usage 表 |
| 输入:输出 token | 56.2M : 0.54M(**103:1**) | llm_usage 表 |
| 工具调用总数 | 863 次(Bash 占 53%) | chat.jsonl |
| 完全重复调用(同名同参) | 62 次(Read 同文件 ×9、同 ffmpeg 命令 ×4) | chat.jsonl |
| 错误结果调用 | 67 次(403/404/Traceback,集中 research 抓站) | chat.jsonl |
| curl/wget 逐站抓站 | 91 次,而正牌 $web_search **仅 1 次** | chat.jsonl + 作品目录 20+ 抓站残片 |
| **重复/无效探索合计** | **~145 次 ≈ 17%** | 保守口径,不含评审驳回连带重做 |
| thinking 块 | 581 个 / 77.2 万字符,**占可见输出 96%** | chat.jsonl |
| 空转续跑风暴 | 30 秒内 14 条"继续执行"(2.2s/条),全程 52 条 | chat.jsonl |

### 代码面证据链(7 环节,环环有物证)

1. **回合结构**:每回合重发全量 system prompt + 全量历史(loop.ts:220-238);
   thinking 模式供应商强制回填全部历史 reasoning(openai-compat.ts:59-66)——
   96% 的思考字符每次请求重新付费。
2. **工具面**:本地工具仅 6 个但 Bash 是万能逃生舱,与 Read/Write/Edit/WebSearch 全面重叠;
   代码注释自证"kimi 连续 100+ 次 bash curl 打转"(ws-bridge.ts:636-638)。
3. **指令形态严重不均**:material-search 有确定性步骤契约(step-contract.ts:118-159,
   通道顺序+逐字命令+失败换策略,**被 2026-08-26 五轮事故逼出来的孤本**);
   research 是开放式目标(api.ts:2139-2168,无搜索源优先级/失败换源规则);
   兜底指令仅两行 "Be thorough and creative"(api.ts:2171-2174)。
4. **经验沉淀为零**:grep 全库无任何向 skills 写回的代码;skills 共 3117 行纯手写;
   feedback-loop/self-evolution 只沉淀"选什么题",不沉淀"怎么执行";
   隐性知识固化的唯一路径 = 等事故→人工加铁律(注释遍布事故记录:
   ws-bridge.ts:294/320/391、step-contract.ts:128)。
5. **反馈非结构化**:评审反馈是"问题+方向性建议"(api.ts:2767-2786),
   无行号无改法;"素材不符"被改描述式假修 ×4 轮(v2 已记)正源于此。
6. **熔断全是杀型**:同参 3 连杀回合(loop.ts:257-261,进展作废)、
   评审 3 轮杀作品(api.ts:2708-2727)、空转 15/60 放弃(ws-bridge.ts:709-718)——
   **没有任何"同一问题重复 N 次→强制换策略/换模型/转人工"的转向型护栏**。
7. **思考不可见不计账**:llm_usage 无 thinking 列(llm-usage.ts:38),
   系统无法回答"多少 token 烧在自我反思上"。

### 与 v2 的关系

病根 10 是 v2 病根 2(机械校验外包给 LLM)和病根 9(prompt 自觉无代码护栏)的
**同源放大器**:指令越开放,LLM 越多临场探索;探索越多,上下文越胀;
上下文越胀,每回合越贵越慢;失败后无换策略机制,就在原地自我否定。
**修复它直接作用于时间模型的主项**:634 次调用砍掉 17% 浪费 + 指令确定性化
减少探索步数 + 思考计量/瘦身,标准模式 ≤90min 的目标才有实现的底座。

## 二、v3 新增主线(接续 v2 的 M0-M9)

### M10 子流水线确定性化:全阶段步骤契约 【P0,最高杠杆】

把 material-search 的孤本契约推广到所有阶段——每个阶段的指令从"做什么"升级为"怎么做":

1. **research 阶段确定性化**(当前最大浪费源):
   - 搜索通道路由表:`$web_search`(kimi 内置)优先 → WebSearch → 结构化 API;
     **明文禁止 curl 抓 html 站**(工具层拦截:Bash 命令含 curl/wget+搜索引擎域名直接拒绝并提示正牌工具);
   - 查询词模板库(政策类/事件类/人物类各一套),失败改写规则(去限定词→换同义词→换源);
   - 产出 schema 强制:信源 URL 必填,无 URL 的趋势条目机器门禁拒收(与 M0 幻觉闸联动)。
2. **assets/assembly 阶段补契约**(占全部 input 的 84%):
   - assets:素材源优先级、命中即停规则(已有部分,补失败分支);
   - assembly:ffmpeg 命令模板库(烧录/拼接/字幕各一个已验证模板),
     **参数级模板化,禁止 agent 自由拼装 ffmpeg 参数**;同文件 Read >3 次提示"内容已在上下文,禁止重读"。
3. **兜底指令废除**:"Be thorough and creative" 两行式指令全部替换为
   对应阶段的最低步骤清单 + 验收 checklist 指针。
4. **每阶段工具白名单**:research 阶段禁用 Write 除 steps/*.json 外的路径、
   assembly 阶段禁用联网工具等——用工具面收窄消灭选择困难。

### M11 经验沉淀闭环:成功轨迹 → Playbook 【P1】

1. **轨迹提炼器**:作品完成后(或评审一轮过时),自动从 chat.jsonl 提取
   该阶段的工具调用序列 → 与契约模板 diff → 高频有效模式回写为
   skills 的 "实测经验" 段(当前 skills 只有"原则",没有"哪条命令真的work")。
2. **事故→规则管道 formalize**:把现在"注释里记铁律"的做法升级为
   结构化 incident 表(症状/根因/规则),规则自动注入对应阶段契约,
   不再靠人工记得改 prompt。
3. **失败模式库**:67 次错误调用、改描述式假修等模式归档,
   契约里显式列出"此路不通"清单(negative knowledge 和 positive 同价)。

### M12 上下文经济学:思考计量与瘦身 【P1】

1. **思考计量**:llm_usage 加 thinking_tokens 列;阶段报表区分正文/思考
   (当前 96% 是思考,优化前必须先能看见)。
2. **思考回填瘦身**:reasoning_content 回填改为"仅最近 N 回合"或摘要回填
   (需实测 Kimi/DeepSeek 对截断回填的容忍度,400 红线已在 openai-compat.ts:59 记录);
   GLM-5.3-flash thinking 不可关闭,接入前需评估其对回合成本的放大。
3. **阶段间上下文隔离**:阶段切换时默认重启上下文(带 steps/*.json 状态摘要),
   不背前一阶段的探索垃圾——compact.ts 的压缩从"120k 被动触发"改为"阶段边界主动执行"。
4. **prompt cache 主动利用**:system prompt 稳定前缀 + 可变后缀排序,
   把 cache_read 从"偶然命中"变"设计命中"(kimi 14.7M 输入全价是 v2 已记的直接损失)。

### M13 转向型护栏:从"杀死"到"换路" 【P1】

1. **重复问题检测升级**:同一 issue 在评审中出现第 2 次 → 反馈自动附加
   "前两轮修法未奏效,禁止原思路,必须从 [备选策略表] 换路";
   备选策略表按问题类型预置(素材不符→换源不换描述;时长不足→加镜头不加水词)。
2. **结构化评审反馈**:evaluator 输出契约升级为 patch 级
   (file + line + 当前值 + 期望值),机械项直接给可执行修复;
   评审模型按 v2-M5 降档后,结构化输出可靠性反而提升。
3. **杀型护栏改造**:同参 3 连不再杀整回合,改为"拒绝该调用 + 返回
   '此路不通,换 [具体备选]'"的工具内拦截(保留回合进展);
   空转续跑的"有进展"判定从"消息块 +3"改为"steps/*.json 有实质写入"。

# 下篇:四路深挖新增病根(2026-08-28 下午)

> 取证范围:跨作品统计(全库 12 作品/1673 条 llm_usage/51 份评审)、人机协同代码面、
> 外部依赖全清点、认知负荷与指令一致性。四路报告证据全部可回溯到 文件:行号 与 SQL/日志。

## 病根 11:跨作品零学习——每次生产都是零经验重开(Learning Loop Absent)

病根 10 是"单作品内重新发明轮子";病根 11 是"**跨作品也不长记性**",四条独立证据:
- **curl 抓站 vs 正牌搜索 = 509:8**(4 作品合计)。已被事故教训过的错在 08-26 最新作品
  原样重犯;05d 甚至把 `$web_search` 当 bash 命令敲(中文搜索词进 shell,Exit 127),
  26 次 `Bash(":")` 纯空操作——agent 对自家工具协议都没学会。
- **失败即换皮重跑**:05d failed 后 5 分钟内 224 换 id 重跑(chat 时间戳 11:44:25→11:44:28),
  eval_attempts 清零,零教训传递。熔断只是换皮重试。
- **同三类 critical 跨 3+ 作品重犯**(时长超标/中文乱码/响度不达标)——完全可做静态预检,
  却每作品烧 LLM 评审去抓。
- **25% 作品是僵尸**(3/12 创建后从未处理,永远 reviewing);8/12 永远停在 reviewing。
- 量化波动即不稳定:plan 阶段 input tokens 跨作品极差 **123 倍**(117K→14.4M);
  material-search 墙钟 46min→189min。

## 病根 12:评审器生命周期失控——墙钟的最大敌人不是 LLM(Evaluator Limbo)

- **评审器可无限挂起**:5e3 评审器僵死 **14 小时**,系统每 20min 给 creator 发相同
  "继续执行",agent 反复答"我应该等待"——creator 陪绑空转,无超时、无接管、无自愈。
  无挂起的 cd5 全程 0 个 >10min 空白。**墙钟方差主因是评审挂起,不是生成慢。**
- **评审结论无约束力**:05d material-search **5 轮评审全 fail,照样标 done 放行**。
  评审在制度上是 advisory 而非 gate(好消息:解析失败兜底 pass 通道实测触发 0 次)。
- **评审模型事实双轨**:带图评审回合被视觉路由劫走 kimi(eval:assembly 58/156 次),
  与配置的 deepseek-pro 并存——评审口径本身不稳定,同一作品不同阶段可能被不同模型评。
- **"下班即断"**:18 点后调用骤降,挂起 14h 期间无任何自愈动作,纯等人工。

## 病根 14:用户被锁在门外——无介入通道、决策不可见(Human Locked Out)

- **AskUserQuestion 是死代码**:loop 支持配对回填、前端渲染了选项卡,但工具从未注册
  (tools/index.ts:37-49)——agent "主动问用户"的通道不存在。
- **介入=杀回合**:sendMessage 发现 loop 在跑就先 abortTurn 杀当前回合(ws-bridge.ts:873-877),
  无"注入当前回合尾部"机制;半成品复用只靠 prompt 软约定。
- **关键决策零事件**:时长在渲染时刻才由素材之和算出(video-factory.ts:148-152);
  agent 为过门禁自行压时长、弃用模版、换素材,全部发生在模型内部——
  "决策前确认"和"决策后即时通知"的代码路径都不存在。"降质必须透明"只是 prompt 软约束。

## 病根 15:外部依赖治理裸奔(Ungoverned Dependencies)

- **无超时流行病**:22 处 fetch 无超时 + 10 处 spawn 无超时(完整清单已取证),
  覆盖 LLM 主链路 SSE、即梦/Seedance、MiniMax 全系、素材下载、5 家发布商全链路、
  健康检查本身。H3 只是被观测到的那一例。
- **额度体系名义三层实际半层**:LLM 有记账但 priceTable 缺配即 cost=0(日熔断永不触发);
  **所有按条计费依赖(即梦/Seedance/Dreamina/OpenRouter/MiniMax/H3 条数)零用量追踪**,
  耗尽时报模糊 API_ERROR,分不清"没钱了"还是"挂了"。
- **登录态垃圾入库根因链**:采集器无登录态门 + scraper 吞异常 + undefined 指标照常落库
  (analytics-collector.ts:76-140 + douyin-scraper.ts:32-37)。
- **磁盘只进不出**:作品目录/渲染缓存/browser-profiles/调试截图全部无清理策略。
- **换机即炸点 11 项**:用户名硬编码进 prompt(ws-bridge.ts:376)、端口 3271 散布 54 处、
  skills 双副本(criteria 已实测漂移:~/.claude 版多出第 7 维)、python3 硬编码等。

## 病根 16:规则通胀与互斥——460 条铁律的反噬(Rule Inflation)

- **认知负荷实测**:典型一回合"必须遵守"文本 20-40k tokens(L0 system prompt 5-6k +
  阶段契约 2.5-5k + 必读 skills 9-33k);硬规则词(必须/禁止/严禁/铁律)全库 **~460 处,
  散布 40+ 文件、5 个注入层**;assets 阶段一回合暴露 ~200+ 条硬规则。
- **16 对互相打架的规则**(对照表已取证),最恶劣形态:
  - **同一 system prompt 内自相矛盾**:python 用 `py -3` 不要用 python3(ws-bridge.ts:321)
    vs 同文件 4 处指令 `python3`(369-398);
  - **同一条消息内互斥**:"禁止 AI 生成"(api.ts:2208) vs 契约"仅 AI 生成"
    (step-contract.ts:58-76);"禁止提问"(api.ts:1879) vs "请用户 3 选 1"(api.ts:2137);
  - **api.ts 点名禁止的 volume=0.15 正是 content-assembly SKILL.md:504 的推荐值**;
  - 字幕位置 MarginV=430 vs 960 两个坐标系;字体三套规则(一处还是 macOS 残留);
  - skill 教授绕过门禁的 PUT 旁路(content-planning:369),一处还是**不存在的死 API**。
- **补丁只进不出**:每条铁律带事故日期戳,无合并/去重/退休机制——"系统第一原则"四条
  逐字重复两处、BGM 响度三处、中文编码四处;skills 尾部段落整段重复两遍;

# 附:第一梯队可行性论证结论(2026-08-28,两路专项验证)

> 验证方式:两路只读代码审查,逐项给"可行/有条件可行/不可行+改动量+最大风险"。
> **结论:5 项全部可行或条件可行,无一推翻;但论证修正了 2 个事实错误、
> 新发现 3 个审计外问题、给出 6 条必须遵守的设计纪律。**

## 论证修正的事实

1. **05d"5 轮 fail 仍放行"的真实形态**(修正病根 12 表述):并非 fail 被忽略,而是
   **eval_blocked 熔断可被 agent 自行复活**——3 轮 fail 杀作品后,advance 端点守卫
   (api.ts:2904-2926)不拦 eval_blocked 状态,agent 再调一次 advance 即重新评审
   (日志实证 7 次 advance)。"3 轮杀作品"不是终态。
2. **criteria 漂移根因**(修正病根 16 表述):同步机制存在(index.ts:158-170)但依赖
   **Windows 上不存在的 rsync**,catch 只 console.warn——每次启动静默失败,
   同步从未工作过。且 rsync `--delete` 若真生效会误删 homedir 里 50+ 个用户个人 skill。

## 论证新发现(审计外)

3. **被 LoopGuard 杀的回合会被 auto-continue 误判"有进展"并清零空转计数**
   (ws-bridge.ts:711 + loop.ts:240/261 交互)——死循环每 4 次调用自我赦免一次,
   15 次空转闸永远打不满。
4. **AskUserQuestion 半激活状态会被自家续跑击穿**:loop 配对回填、前端渲染、
   测试都在,唯独工具未注册;且 scheduleAutoContinue 无 awaiting_user 抑制——
   即使注册,2 秒后"继续执行,不要等确认"会当场击穿任何提问机制。
5. **curl 使用面的真实分布**:内部 localhost API 调用占 70-90%(224: 67/98;
   05d: 103/116)——一律禁 curl 会直接杀死流水线,拦截必须是"外网抓取"精确制导。
   另:本地没有 WebSearch 工具实现,$web_search 是 kimi 独有能力,
   research 档切到 deepseek/glm 时联网搜索直接消失且无告警。
